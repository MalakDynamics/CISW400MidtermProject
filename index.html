tutorial • GSAP animations

Learn to use the GSAP library

GSAP is a wonderful animation library used by award-winning websites and the biggest companies in the world. It can let you manipulate the DOM with incredible precision and turn a static page into a carefully choreographed set-piece.

Much like jQuery, you can do many of the things GSAP does with vanilla JavaScript and CSS, but again, much like jQuery, you'll find yourself writing a lot more code to do the same thing as GSAP, and you are missing out on a wonderful array of plugins that speed up your work and let you do things that might otherwise be inaccessible.

Mind you, this is more than just a jQuery .animate() clone! Unlike jQuery's .animate() library, GSAP has native hardware acceleration for smooth 60+fps animations timed to refresh rate, it can natively touch properties that .animate() cannot without by-frame JavaScript calculations, and it has animation timelines to choreograph complex chains of animations. If you want complex, smooth animations, then GSAP is the library for you!

STEP 02 Basic Movements

item 02-A • Moving Objects with GSAP via gsap.to()

Moving Obects With GSAP: gsap.to()

When thinking about animation, it's important to think about each animation as moving from a "start state" to an "end state." GSAP let's you define an animation by declaring properties from its starting state, from its ending state, or even from both!

Let's start by looking at animating to an end state with the .to() method. If no other animations have been applied, we can treat the original position of the object as the start position of the animation, and then identify its ending state to animate to.

The parameters taken are a target object, written as you would a querySelector target ('.box', '#box', etc.), and an object with all the properties for the animations like positioning and appearence.

item 02-B • combining transformations via gsap.to()

Adding Rotation: gsap.to()

One tween can animate more than one property at a time. Add a rotation value to an object with a move value and GSAP will work out the animation all on its own to move and spin the box together, finishing both at the same moment.

Rotation is measured in degrees. Positive values turn the box clockwise, and you can see the effects in the demo below.

item 02-C • Defining the Start via gsap.from()

Starting Point: gsap.from()

gsap.from() works the other way around from .to(). Instead of saying where the object ends up, you say where it starts, and GSAP animates it back to where it already sits on the page.

This is handy for entrance animations, like sliding a card in from the side when the page loads, because the object's normal spot in your CSS is already the end state you want.

item 02-D • Start-Finish Control via gsap.fromTo()

Start to Finish: gsap.fromTo()

You might have noticed that the play button in the examples so far only works for one click before needing to be reset. That is because the .to() function will compare where the object's current state is with the final state you defined for it, and it will animate the intermediate frames to get to that change. If it's already at it's final state, there's nothing to animate!

If we want to give the object a defined animation that plays out consistently every time, we want to use something that defines a consistent start state and end state. For that, we have the fromTo() function.

STEP 03 Pacing Animations

item 03 • Animating Groups via stagger

Animating Groups: stagger

GSAP can often make animations that would be verbose in CSS occur concisely with GSAP. When a selector matches several elements, gsap.to() can animate all of them. On its own, every element moves at exactly the same time, but GSAP gives us tools to control that sequence.

Adding a stagger value offsets each element's start by that many seconds, so the group moves one after another like a wave. In CSS you would need a separate animation-delay on every element to get the same effect, one line per item animated. In GSAP we can do it in just one property!
